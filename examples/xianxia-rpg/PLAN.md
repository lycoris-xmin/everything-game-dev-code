## 1. 目标与范围

基于 GDD §12.1，本计划覆盖四个交付层级，逐层验证核心假设：

| 层级 | 目标 | 关键交付 |
|------|------|----------|
| **MVP** | 验证"战斗→材料→打造→变强"核心循环是否成立 | 1 个小型区域、1 段短主线、8–12 敌、15–25 装备、回合制战斗、打造台、单存档 |
| **Vertical Slice (VS)** | 验证表现力与系统深度 | +1 区域、真实 2D 手绘资产、编队系统(SYS-009)、灵兽(SYS-013)、任务(SYS-018)、对话(SYS-019) |
| **Alpha** | 全主线可通关 | 全部区域、全部 MVP/VS 系统、客栈/商店(SYS-015/SYS-022)、经脉(SYS-020)、命格(SYS-021) |
| **Full Vision** | 完整内容 | 图鉴(SYS-028)、成就(SYS-029)、无障碍(SYS-030)、全配音/过场（如资源允许） |

**本计划当前聚焦 MVP → VS 的落地路径**，Alpha/Full Vision 仅作依赖与风险预留。

## 2. 里程碑计划

### M0 — 工程脚手架（前置）
- **目标**: 可运行的 Godot 4.7.2 (Mono) + C# 空工程
- **交付**: `project.godot`、`.csproj`、目录结构、Autoload 占位、CI 导出预设(Windows)、`npm run doctor` 自检通过
- **退出标准**: `dotnet build` 通过；F5 能进入空主场景；导出 Windows 包成功
- **依赖**: Godot 4.7.2 Mono、.NET 8 SDK

### M1 — 数据与配置底座（SYS-004 / SYS-001 / SYS-002）
- **目标**: 数值与五灵规则可被代码计算
- **交付**: 属性系统(10 项)、五灵相克/相生环、数据配置加载器(Resource/CSV)、单元测试
- **退出标准**: 输入两套属性可对五灵克制与最终伤害做确定性断言（NUnit 通过）

### M2 — 回合制战斗核心（SYS-006 / SYS-007 / SYS-008 / SYS-010）
- **目标**: 跑通一场完整战斗
- **交付**: AV 行动值队列、技能系统、角色/敌人实体、简单敌方 AI、战斗结算
- **注意**: SYS-006 接口尚未定稿，本里程碑以 GDD §5.2 规则为最小契约（AV 队列 + 韧性击破 + 可插队终结技），详细数值留待设计冻结
- **退出标准**: 4 人队 vs 1 组敌人可打到胜负；战斗日志可回放

### M3 — 探索与遭遇（SYS-016 / SYS-017 / SYS-019）
- **目标**: 在 2D 区域中移动并触发战斗
- **交付**: 区域场景、移动/交互、遭遇触发、对话系统雏形
- **退出标准**: 走完一个区域可触发 3–5 场战斗并进入剧情节点

### M4 — 掉落、打造与养成（SYS-011 / SYS-012 / SYS-014 / SYS-031 / SYS-003）
- **目标**: 闭合核心循环
- **交付**: 固定+随机掉落、材料/物品、装备打造与强化(线性成本、100% 成功)、等级成长
- **退出标准**: "打完一组→材料差 2 个→再打一组→造出装备→面板变强"可在单会话内走通

### M5 — UI 与存档（SYS-023 / SYS-024 / SYS-005 / SYS-015）
- **目标**: 玩家可见且能保存进度
- **交付**: 战斗 HUD(AV 队列/韧性条/五灵提示)、角色面板、打造界面、存档点、存档读写
- **退出标准**: 全部关键路径手柄可导航；存档后重开可恢复

### M6 — 垂直切片整合（VS）
- **目标**: 把 M1–M5 串成可试玩的切片
- **交付**: +1 区域、编队(SYS-009)、灵兽(SYS-013)、任务(SYS-018)、真实 2D 占位→手绘过渡资产
- **退出标准**: 见 §3 垂直切片成功标准

## 3. 垂直切片计划（基于 `docs/templates/vertical-slice-plan.md`）

### 3.1 Objective
证明"玩家能亲手打出一套属于自己的 Build"在 2D 回合制单机 RPG 中成立，且 Godot C# 工程可稳定支撑战斗+打造+探索+叙事四系统并发。

### 3.2 Success Criteria
- **Product**: 核心循环可信；"这是我搭出来的"在 N=5–8 试玩问卷中≥60% 认同；UX 决策同屏可见
- **Technical**: 稳定 60fps（2D，1080p）；单场战斗无 GC 尖刺；存档兼容向前；CI 导出可复现
- **Production**: 跨系统 handoff 清晰（战斗→掉落→打造→UI→存档均有明确接口与负责人）

### 3.3 Slice Scope
- **Included**: 2 区域、短主线 1 段、10 敌、20 装备、编队 4 人、灵兽 1、任务 3、对话全程
- **Presentation**: 真实 2D 手绘占位资产（色块→古风立绘过渡），程序化音效
- **Excluded**: 客栈社交、商店经济深度、经脉/命格、图鉴/成就、全配音

### 3.4 Dependencies
- 设计: SYS-006 战斗数值冻结（最高阻塞）
- 技术: Godot 4.7.2 Mono 与 .NET 8 工具链稳定；C# 测试框架选型（§6）
- 内容: 2D 资产管线（立绘/场景/技能演出）
- QA: 手柄导航、文本缩放 100%–200%、状态三元冗余

### 3.5 Quality Targets
- 战斗手感: 行动顺位可读、击破有反馈
- 美术: 古风可读、状态编码形状+文字+颜色
- 音频: 击破/暴击/硬控有可区分音效
- 性能: 2D 场景 < 8MB 常驻、单场战斗 < 2ms 逻辑帧
- 稳定: 连续 30 分钟试玩无崩溃

### 3.6 Risks
| 风险 | 概率 | 影响 | 缓解 | 触发 |
|------|------|------|------|------|
| SYS-006 战斗未定稿 | 高 | 高 | M2 先用最小契约，数值冻结前不锁 UI | 设计评审未通过 |
| 范围/产能 | 高 | 中 | MVP 严格裁剪，VS 资产用过渡占位 | 周进度落后 20% |
| C# 与 Godot Mono 兼容 | 中 | 高 | M0 即验证 build/export，锁定 4.7.2 | export 失败 |
| Steam 集成未知 | 低 | 中 | M0 预留 Platform 集成层，M6 后接 | 上线需求明确 |

### 3.7 Milestones & Sequence
1. **Prototype** (M1–M2): 可跑战斗与数值
2. **Integration** (M3–M5): 探索+打造+UI+存档闭环
3. **Content-complete slice** (M6): 双区域可玩
4. **Polish & validation**: QA + 试玩 + 性能

### 3.8 Validation Plan
- 试玩 N=5–8，45–60 分钟，问卷验证核心假设
- QA: 手柄导航、1080p/1440p 布局、文本缩放、状态三元冗余
- 性能: Godot Profiler 采单场战斗帧

### 3.9 Exit Decision
- **Forward**: 核心假设验证通过 + 稳定可玩
- **Pivot**: "打造驱动变强"不成立 → 强化战斗外成长反馈
- **Cut**: 产能不足 → 砍 VS 第二区域，保 MVP 闭环

## 5. 风险登记（合并 GDD §12.3）

1. **最高风险 — 范围与产能**: 单人/小团队 3–5 月 MVP；以里程碑裁剪 + 占位资产对冲
2. **美术产能**: 2D 手绘体量；VS 用过渡占位，Full Vision 再补
3. **战斗系统未定稿**: SYS-006 六轮评审中；M2 最小契约先行，冻结前不锁 UI
4. **C#/Godot Mono 工程风险**: M0 即验证 build+export（新增，技术侧）
5. **Steam 集成未知**: 上线需求未明确；M0 预留 Platform 层
